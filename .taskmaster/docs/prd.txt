# 크리에이터 정산 API

## 목표
약 3시간 안에 공개 저장소로 제출 가능한 Spring Boot 백엔드 채용 과제를 완성한다. 기능을 넓히기보다 작고, 설명 가능하며, 테스트 가능한 결과물을 만든다.

## 아키텍처 제약
- 웹 인바운드 어댑터, 애플리케이션 유스케이스·포트, 도메인 계산, JPA 아웃바운드 어댑터만 둔 얇은 헥사고날 구조를 사용한다.
- DDD 모델은 정산 규칙에만 집중한다. 도메인 이벤트, 애그리게이트 프레임워크, 메시지 브로커, 범용 기반 추상화는 만들지 않는다.
- 영속성 엔티티와 순수 정산 계산 타입을 분리한다.
- Java 또는 Kotlin과 H2를 사용한다. 인증은 크리에이터·사용자 ID 파라미터로 간단히 처리할 수 있다.

## 필수 기능
- 판매와 취소를 등록한다. 취소는 원본 판매를 참조하며 원결제 금액을 초과할 수 없다.
- 크리에이터와 기간으로 판매 내역을 조회한다.
- Asia/Seoul 기준으로 크리에이터 한 명의 월별 정산을 조회한다.
- 운영자가 기간별 정산 현황을 조회한다.
- 월별 총 판매액은 paidAt 기준, 환불액은 cancelledAt 기준으로 계산한다. 순 판매액은 총 판매액에서 환불액을 뺀 값이고, 수수료는 순 판매액의 20%, 정산 예정액은 순 판매액에서 수수료를 뺀 값이다.
- 전액 환불, 부분 환불, 월 경계 취소, 빈 월을 포함한 제공 시나리오 데이터를 초기화한다.

## 테스트와 문서
- 제공된 3월 계산, 부분 환불, 월 경계 취소, 판매 없는 월, 초과 환불 거부, HTTP 통합 흐름 한 건만 핵심 테스트로 작성한다.
- README에는 실행·테스트 명령, API 예시, 데이터 모델, KST 경계 규칙, 가정, 설계 이유, 미구현 범위, AI 활용 내역을 작성한다.

## 명시적 제외 범위
- 정산 상태 전이, CSV 내보내기, 수수료율 이력, Docker, 크리에이터·강의 관리 API, 정교한 인증·인가, 광범위한 테스트 커버리지는 구현하지 않는다.

## 작업 생성 조건
- 6~8개의 간결한 작업만 생성한다.
- 모든 작업 제목은 [config], [feature], [test], [docs] 중 정확히 하나의 접두사로 시작한다.
- 의존성을 유지하고, 각 작업은 짧은 집중 작업 단위로 끝낼 수 있게 한다.

## 확정된 구현 결정
- 정산 조회 포트는 집계 금액이 아니라 대상 기간의 원본 판매·취소 자료를 반환하고, 순수 계산기가 정산 결과를 계산한다.
- 금액은 원 단위 `long`으로 저장한다. 음수 순 판매액에는 수수료를 0원으로 제한하고, 음수 정산 예정액은 환불 부담액으로 반환한다.
- 운영자 기간 조회는 KST 기준으로 시작일 포함, 종료일 다음 날 00:00 미만의 반열린 구간을 사용한다.
- 원본 과제에 빠진 취소 초기 데이터는 기대 결과를 재현하도록 직접 정의하고, 보완 근거를 README에 남긴다.
- 판매별 환불 상태는 저장하지 않고 연결된 취소 금액의 합계에서 계산한다. 누적 환불액이 원결제 금액을 초과하면 거부한다.
- `X-Actor-Id`, `X-Actor-Role` 헤더로 과제용 단순 접근 경계를 적용한다. 실제 인증이 아니라는 점을 README에 명시한다.
- 이름 있는 도메인 예외와 전역 예외 처리기를 두며, 핵심 명령·조회 성공과 도메인 실패를 기본 로그로 남긴다.
